# Remediation Log: Security, Consistency & Architecture Fixes
**Project:** AI Novel-to-Webtoon Studio  
**Date:** 2026-10-22  
**Auditor & Remediation Lead:** Antigravity Senior Software Architect & Security Reviewer

## 1. Executive Summary

During the comprehensive audit of the AI Novel-to-Webtoon Studio, nine discrete issues spanning application security (BOLA/IDOR, path traversal, unauthorized document access), AI provider transparency, character consistency propagation, export approval gates, framework deprecations, and frontend reactivity were identified, remediated, and verified through automated test suites.

All 17 backend tests (including 5 newly authored regression tests) pass with 0 deprecation warnings (reduced from 647). The frontend linter passes with 0 warnings or errors, and the visual benchmark harness runs deterministically.

## 2. Itemized Remediation Log

### SEC-01: Broken Object-Level Authorization (BOLA / IDOR) on API Endpoints
- **Severity:** High
- **Category:** Application Security / Authorization
- **Root Cause:**
  Endpoints in `projects.py`, `documents.py`, `references.py`, `analysis.py`, `planning.py`, `storyboard.py`, `generation.py`, `export.py`, and `jobs.py` accepted `project_id` UUIDs directly from path parameters or query strings without asserting that the authenticated user (`user_id` from `get_current_user_id`) was the owner or an authorized collaborator on the target project.
- **Affected Files:**
  - `backend/app/core/security.py`
  - `backend/app/api/v1/projects.py`
  - `backend/app/api/v1/documents.py`
  - `backend/app/api/v1/references.py`
  - `backend/app/api/v1/analysis.py`
  - `backend/app/api/v1/planning.py`
  - `backend/app/api/v1/storyboard.py`
  - `backend/app/api/v1/generation.py`
  - `backend/app/api/v1/export.py`
  - `backend/app/api/v1/jobs.py`
- **Safe Fix Applied:**
  1. Implemented `verify_project_access(project_id: UUID, user_id: str, db: AsyncSession)` in `backend/app/core/security.py`.
  2. Integrated `verify_project_access` as an explicit guard across all read and write endpoints. If the user does not own or have permission to access the project, the system raises an `HTTPException(status_code=403, detail="Access denied: user is not authorized for this project")`.
- **Regression Test / Verification:**
  - `test_01_cross_user_project_access_blocked` in `backend/tests/test_13_security_and_remediations.py`.
  - Confirmed: Unauthorized user attempting to access another user's project receives HTTP 403 Forbidden.
- **Status:** **FIXED & VERIFIED**

### SEC-02: Unrestricted Static Storage Endpoint Serving Raw Manuscript Documents
- **Severity:** High
- **Category:** Application Security / Information Disclosure
- **Root Cause:**
  `GET /api/v1/storage/{category}/{filename}` in `backend/app/api/v1/assets.py` served files directly from filesystem storage without checking category sensitivity. Private novel manuscripts stored in `storage/documents/` could be downloaded without authentication by anyone who enumerated or guessed the filename.
- **Affected Files:**
  - `backend/app/api/v1/assets.py`
  - `backend/app/core/security.py`
- **Safe Fix Applied:**
  1. Added a strict category whitelist to `GET /api/v1/storage/{category}/{filename}` allowing only public visual assets: `{"references", "assets", "exports"}`.
  2. Access to raw manuscripts (`"documents"`) via the unauthenticated static asset endpoint is explicitly rejected with `HTTPException(status_code=403, detail="Direct access to private document storage is forbidden.")`.
  3. Strengthened `get_safe_storage_path` in `backend/app/core/security.py` to use Python 3 `target_path.resolve().relative_to(base.resolve())` to provide absolute path traversal protection.
- **Regression Test / Verification:**
  - `test_02_storage_private_document_category_blocked` in `backend/tests/test_13_security_and_remediations.py`.
  - Confirmed: Direct requests to `/api/v1/storage/documents/sensitive_novel.txt` return HTTP 403 Forbidden.
- **Status:** **FIXED & VERIFIED**

### SEC-03 / PROV-01: Silent AI Provider Fallback Violating Provider Honesty Requirement
- **Severity:** Medium
- **Category:** AI Pipeline / Integrity
- **Root Cause:**
  `backend/app/providers/factory.py` silently caught configuration failures or missing API keys when `openai`, `gemini`, or `stability` were requested, falling back to `MockLLMProvider` or `MockImageProvider` with only a logger warning. This masked configuration failures and could lead users to believe that procedural mock illustrations were generated by real cloud models.
- **Affected Files:**
  - `backend/app/providers/factory.py`
- **Safe Fix Applied:**
  Refactored `get_llm_provider` and `get_image_provider` in `backend/app/providers/factory.py` to raise an explicit `RuntimeError` when a non-mock provider is requested without valid credentials or required packages. Only explicitly configured `mock` providers return mock instances.
- **Regression Test / Verification:**
  - `test_03_unconfigured_real_provider_fails_honestly` in `backend/tests/test_13_security_and_remediations.py`.
  - Confirmed: Attempting to instantiate unconfigured `openai` or `stability` providers raises `RuntimeError` rather than silently degrading to mock output.
- **Status:** **FIXED & VERIFIED**

### SEC-04 / EXP-01: Permissive Export Defaults Permitting Unapproved Panels & Placeholder Stitches
- **Severity:** Medium
- **Category:** Workflow Governance / Creative Control
- **Root Cause:**
  1. In `backend/app/api/v1/export.py`, the query parameter `require_all_approved` defaulted to `False` (`Query(False)`), allowing unapproved panels to be exported by default.
  2. In `backend/app/export/webtoon_exporter.py`, missing panel assets generated procedural fallback placeholder blocks rather than halting export and enforcing approval.
- **Affected Files:**
  - `backend/app/api/v1/export.py`
  - `backend/app/export/webtoon_exporter.py`
- **Safe Fix Applied:**
  1. Changed the default parameter in `backend/app/api/v1/export.py` to `require_all_approved: bool = Query(True)`.
  2. Enforced strict validation in `webtoon_exporter.py`: if `require_all_approved` is `True` and any panel is unapproved or lacks generated artwork, export halts immediately and raises `ValueError`.
- **Regression Test / Verification:**
  - `test_04_export_enforces_approval_by_default` in `backend/tests/test_13_security_and_remediations.py`.
  - Confirmed: Calling export on an episode with unapproved panels fails with HTTP 400 Bad Request.
- **Status:** **FIXED & VERIFIED**

### SEC-05 / ART-01: Unscoped Style Profile Lookup in Background Job Runner
- **Severity:** Low / Medium
- **Category:** Visual Consistency / Multitenancy
- **Root Cause:**
  In `backend/app/workers/job_runner.py` (line 189), the style profile version query queried `StyleProfileVersion` ordered by `created_at.desc()` without filtering by `project_id`, potentially applying another project's style profile version in multi-project deployments.
- **Affected Files:**
  - `backend/app/workers/job_runner.py`
- **Safe Fix Applied:**
  Updated the query to explicitly filter by project: `.where(StyleProfileVersion.project_id == job.project_id)`.
- **Regression Test / Verification:**
  - Verified across job execution pipeline in `backend/tests/test_07_08_revision_stale.py` and `backend/tests/test_13_security_and_remediations.py`.
- **Status:** **FIXED & VERIFIED**

### ART-02 / CONS-01: Character References Dropped During Generation & Provenance Tracking
- **Severity:** Medium
- **Category:** Character Consistency / Asset Dependencies
- **Root Cause:**
  In `backend/app/workers/job_runner.py`, `character_refs` was hardcoded to `[]` when calling `img_provider.generate_draft` and `img_provider.generate_final`. Primary character reference assets uploaded by the creator were not passed to the visual engine or recorded in `AssetDependency`.
- **Affected Files:**
  - `backend/app/workers/job_runner.py`
  - `backend/app/models/style.py`
  - `backend/app/services/versioning.py`
- **Safe Fix Applied:**
  1. Updated `job_runner.py` to extract character identifiers present in panel beats, query `Character` records and associated active `CharacterReference` sheets.
  2. Passed active character appearance details and reference assets into `generate_draft` and `generate_final`.
  3. Added explicit relationship `reference_asset: Mapped["ReferenceAsset"] = relationship("ReferenceAsset", lazy="selectin")` in `backend/app/models/style.py`.
  4. Updated `versioning_service.record_dependencies` to record dependencies for both `character_id` and nested `reference_asset_id`s in `AssetDependency`.
- **Regression Test / Verification:**
  - `test_05_character_reference_propagation` in `backend/tests/test_13_security_and_remediations.py`.
  - Confirmed: Background generation records character and reference asset dependencies in the `AssetDependency` table.
- **Status:** **FIXED & VERIFIED**

### DEP-01: 647 Deprecation Warnings in Backend Pytest Suite
- **Severity:** Low
- **Category:** Code Quality / Maintenance
- **Root Cause:**
  Models and schemas used deprecated Pydantic v1 `class Config: orm_mode = True` and deprecated `datetime.utcnow()` from Python standard library.
- **Affected Files:**
  - `backend/app/schemas/bible.py`
  - `backend/app/schemas/asset.py`
  - `backend/app/schemas/adaptation.py`
  - `backend/app/schemas/project.py`
  - `backend/app/schemas/style.py`
  - `backend/app/core/config.py`
  - `backend/app/models/base.py`
- **Safe Fix Applied:**
  1. Converted all schema classes to Pydantic V2 `model_config = ConfigDict(from_attributes=True)`.
  2. Replaced `datetime.utcnow()` with `datetime.now(timezone.utc)`.
- **Regression Test / Verification:**
  - Executed `pytest backend/tests -v`. Deprecation warnings dropped from 647 to **0**.
- **Status:** **FIXED & VERIFIED**

### HOOK-01: Frontend React Hook Missing Dependencies (`react-hooks/exhaustive-deps`)

- **Category:** Frontend Stability & Reactivity
- **Root Cause:**

- **Affected Files:**
  - `frontend/src/app/page.tsx`
  - `frontend/src/components/IllustrationReview.tsx`
  - `frontend/src/components/QAReportModal.tsx`
  - `frontend/src/components/WebtoonReader.tsx`
  - `frontend/.eslintrc.json` (created to enforce Next.js Core Web Vitals)
- **Safe Fix Applied:**
  1. Wrapped data-fetching functions in `useCallback` with complete dependencies.
  2. Fixed dependency arrays in components.
  3. Added `.eslintrc.json` configured with `"extends": ["next/core-web-vitals"]`.
- **Regression Test / Verification:**
  - `npm run lint` in `frontend/` reports `✔ No ESLint warnings or errors`.
  - `npx tsc --noEmit` reports 0 TypeScript errors.
  - `npm run build` succeeds cleanly.
- **Status:** **FIXED & VERIFIED**

- **Severity:** Low
- **Category:** Developer Tooling
- **Root Cause:**

- **Affected Files:**
